# Agentic Studio 0.5.1 — pre-publication security review

[Español](../../releases/0.5.1-security.md) · English

Date: October 24, 2026. Source review and local tests with fictitious data. This is not an independent audit or proof that no vulnerabilities remain. AS-2026-* identifiers are internal references, not CVEs.

## Findings and fixes

| ID | Severity | Problem | Fix | Verification |
| --- | --- | --- | --- | --- |
| AS-2026-01 | High | A race between project-path validation and opening the file could allow a substituted symlink to redirect reads/writes outside the selected folder. Existing hard links were not rejected. | Descriptor-relative IO, directory opens with `O_NOFOLLOW`, regular-file/link-count checks, bounded 2 MB reads, exclusive temporary files and atomic replacement. Proposals and hashes use the same protected reads. | Symlink, hard-link, FIFO, traversal, parent substitution and late leaf substitution tests; external files remain unchanged. |
| AS-2026-02 | High, LAN availability | TLS negotiation ran in the accept loop. An incomplete handshake could block new connections, and worker count had no explicit limit. | Worker-based TLS handshakes with a 15-second socket timeout and a maximum of 32 connections. The local backend uses the same capacity limit. | A real silent TCP client does not prevent another client from completing TLS, pairing and querying its project. Stalled-handshake shutdown and capacity checks also pass. |
| AS-2026-03 | Medium | Local session bootstrap ran before Host/Origin checks. It required the token but had weaker boundary checks than the API. | Exact Host and Origin checks before setting the cookie. | Foreign-Host and foreign-Origin bootstrap requests receive no session cookie. |
| AS-2026-04 | Medium, local privacy | The database could inherit a umask allowing other local accounts to read it. | No-follow database open, rejection of special files and multiple links, database mode `0600`, new private directories `0700` and backup files `0600`. | File-mode check and rejection of a database symlink. |
| AS-2026-05 | Low | Non-object JSON bodies could cause unhandled exceptions in mobile routes. | Require JSON objects and reject ambiguous Transfer-Encoding at both entry points. | Lists, null, strings and numbers receive HTTP 400 at the gateway. |

## Verified controls

- Local authentication and rejection of missing sessions or foreign origins.
- Project and write/execute permission isolation, including real Seatbelt command/descendant isolation. Commands fail closed if isolation is unavailable.
- HTTPS gateway: single-use pairing, authorized-project sessions, mobile administrative-route denial and revocation after permission changes.
- MCP OAuth: PKCE S256, single-use state, issuer/resource validation and rejection of scope expansion. Uncertain remote tool operations are not retried automatically.
- OpenAI adapter: built-in tools are denied; requested actions pass through project permissions. Tests do not replace account-owner consent.
- Dynamic UI data is escaped and CSP is used. The agent browser is separate from the native bridge and restricted to approved origins.

Detailed local QA evidence is excluded from public packages to avoid disclosing workstation paths and data. Fictitious regression tests are included in the source.

## Limits and distribution

- Remote MCP tools can act on their own service. The user approves read-only declarations; the client cannot enforce file isolation or the absence of external effects on an independent server.
- Allowing write or execution permits changes inside the project. Prompt injection in documents/tool results remains a risk. Permissions and human review are the boundary, not guaranteed model obedience.
- Configured engine and MCP executables must be trusted. Local inference engines run native code outside the agent-command sandbox.
- The application does not encrypt databases or working folders. `chmod` depends on the filesystem; volumes without Unix permissions do not gain inter-user protection from these modes. User backups may also contain conversations.
- The threat model does not include a malicious process already controlling the macOS account, backend code or installation directory.
- macOS uses ad hoc signing and is not notarized. The public IPA has no personal signature and needs valid signing for physical installation.
- Distribution closure includes rebuilt packages, clean install/update checks and an allowlisted public-source export. Databases, tokens, LAN keys, personal signing material and QA logs are excluded.

## Validation result

73 regression tests passed. UI validation covered three viewport sizes without horizontal overflow or JavaScript errors. The installed Mac app preserves existing projects, sessions and messages by hash and retains OpenAI access. The user confirmed the new name and icon on a physical iPad. MoE inference was not repeated for branding and IO security changes; the earlier specific CPU validation remains separately identified.
